# v0.10 — Telegram Bot + Notification Dispatch

## Current state (end of v0.9.x)

- Web UI with auth (admin/analyst/viewer roles)
- Per-user notification preferences (5 categories)
- Telegram deep-link token system (tokens created, not consumed)
- `telegram_link_token` table ready
- No bot listener yet — tokens are generated but never redeemed

## What v0.10 needs

### 1. Telegram bot listener

A long-running process (or systemd service) that:
1. Polls Telegram Bot API for updates (`getUpdates` long-poll)
2. On `/start <token>`: look up token in `telegram_link_token`, consume it,
   write `telegram_chat_id` + `telegram_username` to `user` table
3. On `/help`: reply with available commands
4. On `/status`: show user's notification prefs summary
5. On `/unlink`: clear `telegram_chat_id` (same as web unlink)

**No webhook needed** — long-poll is simpler for a single-user/small-team tool.

```python
# horus/bot/telegram.py (new)
# python -m horus.bot.telegram --token <bot_token>
```

Dependencies: only `urllib` (already in stdlib) — no extra packages.

### 2. Notification dispatch

The pipeline already knows what happened each run. What's missing is the
dispatch step that decides who to notify.

**Approach**: a new `notifications.dispatch` module called at the end of
each pipeline run. It:

1. Queries all users with `telegram_chat_id IS NOT NULL`
2. For each user, checks their `notification_pref`
3. For each enabled category, checks if the current run produced matching
   events (new KEV, EPSS jump, critical CVE+PoC, watchlist match, new PoC)
4. Sends a formatted message via Telegram Bot API

**Message format** (match existing Markdown report style):

```
🔴 NEW KEV ADDITION
CVE-2026-XXXX — CVSS 9.8 CRITICAL
https://nvd.nist.gov/vuln/detail/CVE-2026-XXXX

━━━━━━━━━━━━━━━━━━━━━━
Horus v0.10 · /status
```

### 3. Pipeline plugin hook

Add `on_run_end(result: PipelineResult)` lifecycle hook to the pipeline.
The notification dispatcher plugs in here, so sources/enrichers don't need
to know about notifications.

```python
# In pipeline.py, after render phase:
for hook in _END_HOOKS:
    hook(result)
```

### 4. Horus CLI integration

Add `--bot` flag to `horus --server` that starts the Telegram listener as
a background thread alongside the scheduler.

```yaml
# horus.yaml additions
telegram:
  bot_token: ""        # or TELEGRAM_BOT_TOKEN env var
  enabled: false
```

### 5. Bot command reference

| Command | Description |
|---------|-------------|
| `/start <token>` | Link Horus account (generated in web UI) |
| `/help` | Show available commands |
| `/status` | Show current notification preferences |
| `/kev` | List KEV CVEs since last notification |
| `/watchlist` | Show team watchlist summary |
| `/unlink` | Disconnect Telegram |
| `/pause` | Pause notifications (_resume_ with `/start`) |

### 7. Bot token security

- Bot token stored in env var `TELEGRAM_BOT_TOKEN`, never in DB
- Web UI only shows the bot username link for deep-link
- Bot only responds to registered users (validated via token)
- No group chat support in v0.10 — DM only
