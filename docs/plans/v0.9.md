# Horus v0.9 — Data Quality & Web Filters

*Date: 2026-06-11*

## Goal
Fix data quality issues (product data, PoC→CVE linking) and add web dashboard filters.

## Changes

### Product Data Quality
- **CPE parser improvements**: normalize vendor/product names, skip wildcards/empty values
- **600+ vendor aliases**: `microsoft_corporation` → `microsoft`, `google_llc` → `google`, etc.
- **400+ product aliases**: `google_chrome` → `chrome`, `red_hat_enterprise_linux` → `redhat`, etc.
- **Description-based fallback**: when CPE gives `unknown`, scan description for known vendor/product names
- **150+ keyword mappings** for description extraction

### PoC → CVE Linking
- `poc_from_github()` now scans URL for CVE IDs (not just repo name + description)
- `poc_from_gitlab()` same fix
- Pipeline already calls `link_poc_to_cve()` — now `cve_refs` are actually populated
- Next pipeline run will link existing PoCs to CVEs

### Web UI Improvements
- **Vendor-grouped products** on CVE detail page (vendor → product → versions hierarchy)
- **CVE badges in PoC list** — each PoC shows linked CVEs as clickable badges
- **Version badges** — each version displayed as a separate badge (not comma-joined string)

### Files Changed
| File | Change |
|------|--------|
| `horus/sources/nvd.py` | CPE parser: normalize, skip wildcards, 600+ vendor aliases, 400+ product aliases |
| `horus/core/merge.py` | Description-based vendor fallback, 150+ keywords, PoC URL scanning |
| `horus/web/queries.py` | `group_products_by_vendor()`, `fetch_pocs()` joins `poc_cve` |
| `horus/web/templates/cve_detail.html` | Vendor-grouped product display |
| `horus/web/templates/list.html` | CVE badges in PoC list, version badge rendering |
| `horus/web/static/horus.css` | Vendor grouping styles, version badge styles, PoC CVE badge styles |
