# Horus v0.12 — CTI Platform Upgrade: Dark Web Intel, Trust Scoring, Dashboard

## Overview

Transform Horus from PoC scanner to full CTI platform. Add dark web indicators, trust scoring, OpenCTI-style dashboard, and PoC source expansion.

## Current State (v0.11)

- Sources: NVD (CVE), GitHub (PoCs), X/Twitter (social), Exploit-DB (exploits)
- Enrichers: KEV, EPSS
- Dashboard: KPI cards, severity trend, attack tags
- Model: CVE + PoC dataclasses with reputation_score

### 2. Trust Scoring System

Add confidence layer to CVE model:

```python
# horus/core/model.py
trust_score: float = 0.0  # 0-100 aggregate trust
# Breakdown fields
trust_nvd: float = 1.0    # 1.0 = confirmed
trust_intelx: float = 0.0 # 0-1.0 based on dark web hits
trust_threatfox: float = 0.0
trust_hudsonrock: float = 0.0
trust_phish: float = 0.0
```

Trust algorithm in `horus/core/merge.py`:
```
trust_score = (
  40 * nvd_confirmed +
  25 * intelx_darkweb_mentions +
  15 * threatfox_ioc_count +
  10 * hudsonrock_stealer_hits +
  10 * phish_reports
)
```

### 5. Regex Audit

Current pattern in `horus/core/filters.py`:
```python
_CVE_RE = re.compile(r"CVE[-_]\d{4}[-_]\d{4,}", re.IGNORECASE)
```

Issues found:
- Accepts `CVE_2026_31431` (underscore) — valid but rare
- No validation against future years (>2026)
- No bound on CVE ID length (some test cases have 8+ digits)

Proposed fix:
```python
_CVE_RE = re.compile(r"\bCVE[-_](\d{4})[-_](\d{4,7})\b", re.IGNORECASE)
# Validate year is <= current + 1
# Validate ID length 4-7 digits
```

False positives in `LOW_VALUE_KEYWORDS` — audit needed:
- "cve" (catches too many)
- "poc" (catches non-PoC repos)
- "exploit-db" vs "exploitdb" variants
